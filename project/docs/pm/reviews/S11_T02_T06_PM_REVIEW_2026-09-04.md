## 3. Findings

### [P1] Audio-only completion can authorize full project readiness

**Locations**

- `app/persistence/qc_check_runs.py:120-216`
- `app/persistence/qc_check_runs.py:255-320`
- `app/persistence/readiness.py:222-233`
- `app/services/qc_av_recheck.py:298`

`latest_check_run_state()` lists all `RUN_QC_CHECKS` jobs for the video and
selects `run_jobs[0]` without requiring the run to represent `SCOPE_FULL` or a
complete ten-detector envelope. `check_run_readiness()` then accepts a completed
current run with no unresolved blockers. T04C deliberately creates audio-only
runs, so the newest audio-only run can become the authority consumed by project
readiness.

An independent real-SQLite probe upgraded to current Alembic head, created one
video, and recorded exactly one completed `SCOPE_AUDIO` job containing the two
audio detectors. Actual result:

```text
actual_status=ready
run_state=completed
expected_status=not_run
unexecuted_visual_checks=8
```

This violates T05A AC2: a video must not become ready without a completed,
current, full-scope QC authority. Existing T05A tests seed `SCOPE_FULL`, but the
completion fixture contains only two audio detector names; therefore they also
do not prove complete detector coverage.

**Required correction invariants**

1. Current completed audio-only run with no full run => `not_run`.
2. Current completed full run followed by newer audio-only run => retain the
   full-run authority; any newly opened audio blocker still blocks readiness.
3. Newest matching full run queued/running/failed/stale => `not_run`, even when
   an older full run completed.
4. Manifest/completion scope, fingerprint or detector-envelope mismatch => fail
   closed.
5. A full completion proves all ten detectors, `errors == 0` and `skipped == 0`.
6. A completed current full run with zero items remains a valid ready candidate.
7. The project/API aggregate reproduces and rejects the audio-only case.

**Ownership:** mechanism correction resumes exact S11-T03G owner
`20260903_170546_0d42f6`; consumer/API regression resumes exact S11-T05A owner
`20260903_203404_4a4548` after T03G is integrated.
