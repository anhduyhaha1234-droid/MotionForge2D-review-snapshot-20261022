### F2 — P1: Chromium restart kills an unverified port owner and leaks its replacement

**Owner:** S09-T06B, resume session `20260824_131423_423e42`  
**Code:**
`frontend/e2e/s09-t06bc4-targeted-regeneration.spec.ts:1053-1069` and
`frontend/e2e/s09-t06bc4-helpers.ts:134-149`

The test enumerates every listener on port 8201 and runs `Stop-Process -Force`
without checking PID ownership, command line, runtime root or whether the
process belongs to this test. It then launches `_primaryRelaunched`, discards
the handle with `void`, and reaches the end of the test without stopping that
process in a `finally` block.

The helper's hard-kill fallback is also an unreferenced `setTimeout(...).unref()`
while callers wait only 1.5 seconds, so termination is not an awaited binary
postcondition.

**Impact:** the acceptance can kill an unrelated user service and can leave an
owned backend running on success or failure. Manual Manager cleanup after the
suite does not make the test safe.

**Required correction:** the test must launch and retain its own exact backend
handle/PID, stop only that owned PID/tree, await exit with a bounded timeout,
and wrap primary, restarted and alternate lifecycles in `try/finally`. No
kill-by-port command is permitted. Final assertions must prove owned PIDs exited
and owned ports are free without touching unrelated processes.
