6. **Resource-heavy.** Each Redroid instance = 1-2GB RAM. Running 10+ instances needs a beefy server.

7. **🔴 Damru Chrome split APK installation FAILS on Redroid (2026-07-25 verified).** Chrome on Redroid installs as split APKs (`base.apk` + `split_chrome.apk` + `google_trichrome_library.apk` etc.) but the activities don't register properly. `am start -n com.android.chrome/org.chromium.chrome.browser.ChromeTabbedActivity` returns "Activity class does not exist." `monkey -p com.android.chrome` returns "No activities found." Even Damru's own `stealth-open-url --mode native` fails with the same error. **Root cause:** Redroid's package manager doesn't properly resolve split APK activity classes. **Workaround:** Use Damru's `bake-image` command to create a pre-baked image with Chrome pre-installed and activities properly registered. Or use a full Android emulator (Genymotion, Android Studio AVD) instead of Redroid for Chrome-based automation. `damru install-apks` downloads the APKs but they're not installed on the device — the command is a no-op if the APK files already exist locally.

8. **🔴 Redroid container "Can't find service: package" / "Can't find service: activity" (2026-07-25).** After container restart, Android services may not be fully initialized even when `sys.boot_completed=1`. Symptoms: `pm install`, `pm uninstall`, `am start`, `settings put` all return "Can't find service: X." **Fix:** Wait 60+ seconds after `docker start` before interacting. If services are still missing, the container needs a full `docker rm` + `docker run` (not just `docker restart`). Port binding conflicts: `docker rm` may leave the port allocated — kill all containers first with `docker ps -q | xargs docker kill` then `docker ps -aq | xargs docker rm`.

9. **🔴 Redroid port 5600 binding conflict (2026-07-25).** When recreating Redroid containers, the old container's port binding (`0.0.0.0:5600->5555/tcp`) persists even after `docker stop`. New `docker run -p 5600:5555` fails with "Bind for 0.0.0.0:5600 failed: port is already allocated." **Fix:** Always `docker rm -f <name>` before creating a new container with the same port. If that fails, kill ALL containers: `docker ps -aq | xargs docker rm -f`.
